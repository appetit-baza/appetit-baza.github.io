## 2. Листы Google-таблицы

- **Админы**: ФИО | Филиал | PIN | Активен | Роль | Фамилия Имя (для чата).
  - «Фамилия Имя (для чата)» (столбец F) — так администратор подписан в сообщении о выручке в чате MAX. Пусто — берётся ФИО из столбца A. Столбец A не менять: по нему сайт узнаёт «свои» смены.
  - Роль пустая — обычный администратор: видит только свои смены.
  - «руководитель» — страница «Все смены», решает исправления.
  - «просмотр» — видит всё, как руководитель, но ничего не меняет (так заведена Гульнара).
- **Отчёты**: одна строка на смену.
  - A–X: выручка по типам оплат, 041, курьеры, расходы, приход, «Передана сумма», ID, «Заменён отчётом», «Безнал факт (по сверкам)».
  - Y–AB: самовывоз и доставка, количество и сумма.
- **Курьеры**: по курьеру на строку: часы, заказы, итого, изъятие, «По зонам», доплаты.
- **Доплаты курьерам**: Довоз (зона, причина), Отказ (зона, комментарий), Шашка, Листовки, Наклейка (2000), Другое.
- **Приход-расход**: статьи прихода и расхода; дата = дата смены. Столбец I «Занесено в iiko» — галочка руководителя (кто и когда отметил).
- **Остатки касс**: стартовый остаток кассы по филиалу на начало дня (вносит руководитель на вкладке «Касса»).
- **Справочник курьеров**: Филиал | ФИО | Активен.
- **Исправления**: запросы админов на исправление отправленной смены и решения руководителя.
- **Черновики**: копия черновика каждого админа (чтобы не потерять при выключении компьютера).
- **Журнал входов**: входы, отправки, исправления, резервные копии.
- **iiko: типы оплат**: соответствие типов оплат iiko полям сайта (заполняется само, незнакомые типы надо подписать).

## 3. Форма админа (что договорились)

1. **Сводка и выручка.**
   - Поля по порядку: Онлайн, Наличные, Карта, Яндекс/Деливери, Чиббис, Сбермаркет, Бонусы iiko (это скидка — в «Выручку всего» не входят, как в отчёте 041; в чат идут отдельной строкой).
   - Блок «Заказы»: самовывоз и доставка, количество и сумма; «Общее» должно совпасть с выручкой.
   - Блок «Сверка» (в чат не идёт): «Итого по 041» и «Безнал факт (по сверкам)». Карта должна быть равна безналу; если нет — подсветка у админа и у руководителя.
2. **Курьеры** (по умолчанию одна строка).
   - Ставка за час — 140 ₽ (`RATE` в index.html). «За часы» считается само и вручную не правится.
   - **Казань**: количество и сумма обычно из iiko; если iiko не работает — «Посчитать по зонам»:
     - Жёлтая 0–2,5 км — 165 ₽;
     - Зелёная 2,5–5 км — 205 ₽;
     - Синяя 5–8 км — 245 ₽;
     - Красная 8–11 км — 265 ₽;
     - Фиолетовая 11–20 км — 285 ₽.
   - **Челябинск**: часовую не считаем (её выдают 2 раза в месяц); количество и сумма вручную; километраж — по желанию.
   - **Уфа**: заказы по километражу, обязательно. Тарифы (как в Челябинске):
     - 0–2,5 км — 165 ₽;
     - 2,5–5 км — 205 ₽;
     - 5–7 км — 235 ₽;
     - 7–9 км — 255 ₽;
     - 9–10 км — 265 ₽;
     - 10–11 км — 275 ₽;
     - 11–30 км — 295 ₽.
   - **Изъятие**: сделано / не сделано / частично (при «частично» — сумма с изъятием).
   - **Доплаты**: Довоз (зона + одна из 4 причин: админ, кухня, курьер недокомплект, ошибка КЦ), Отказ (зона × количество), Шашка, Листовки, Наклейка 2000 ₽, Другое.
3. **Приход и расход.** Приход сверху. Статью можно написать свою. Дат у строк нет. На «Переданную сумму» не влияют.
4. **Передана сумма** = Наличные − выплаты курьерам с изъятием.
5. **Отправка.**
   - Excel скачивают до отправки.
   - «Отправить в бухгалтерию» сохраняет отчёт, очищает форму и **сам отправляет выручку в чат «АДМИНЫ АППЕТИТ»**. Исправленные отчёты в чат не уходят. Отдельной кнопки чата нет.
6. **Черновик** сохраняется сам: в браузере и на листе «Черновики».
7. **Исправление** отправленной смены — только после разрешения руководителя. Старый отчёт сохраняется с пометкой «Заменён отчётом».

**Сообщение в чат**:
- филиал жирным заглавными;
- дата и администратор;
- выручка по типам и «ВСЕГО»;
- самовывоз, доставка, общее;
- «🚚 Довозы: N — причины» и «❌ Отказы: N».

## 4. Страница руководителя «Все смены»

Фильтр по филиалу и периоду. Вкладки:

- **Итоги**: плитки, разбивка по филиалам, денежные движения по статьям (статьи с номером чека собираются в одну), доплаты и довозы, список отчётов. В списке видно «в iiko занесено N из M» или «✓ занесено в iiko».
- **В iiko**: сводка «к занесению в iiko» — приходы и расходы по кассам iiko (Касса Казань Глушко 1.01.03 и т.д.) по дням, только незанесённые; галочки по строке и «отметить день».
- **Касса**: остаток кассы по каждому филиалу по дням.
  - Остаток = остаток на начало дня + наличные − курьерам из кассы + приход − расход.
  - Старт вносится вручную (дата и сумма из iiko). Дни без отчёта отмечаются.
- **Сверка с iiko**: выручка по типам оплат из iiko против отчётов админов. Работает после внесения ключей iiko (раздел 7).
- **Сдача отчётов**:
  - календарь филиалы × дни: вовремя — до 12:00 следующего дня, с опозданием, нет отчёта;
  - таблица по администраторам.
- **Выручка**: график по дням, сравнение с прошлым периодом, средняя по дням недели.
- **Оплаты**: доли типов оплат, изменения, суммы агрегаторов.
- **Курьеры**: процент от выручки, средняя за заказ, рейтинг курьеров.
- **Довозы**: доля от заказов, причины по филиалам и администраторам.
- **Сверка**: карта ≠ безнал по сверкам.
- **Excel** — по листу на каждую вкладку.

**Карточка смены**:
- плитки итогов, включая «Остаток кассы»;
- оплаты и сверка рядом; курьеры с доплатами;
- приход и расход с галочками «в iiko» и кнопкой «Всё занесено в iiko»;
- переход к соседним сменам филиала.

## 5. Как вносить изменения

**Сайт** — правка `kassa/index.html` в репозитории GitHub, публикация через GitHub Pages примерно за минуту.
- **Обязательно** увеличить на 1 и `const BUILD='NN'` в index.html, и число в `kassa/version.txt`: тогда страница у админов обновится сама.

**Скрипт Google** (живой код в Apps Script — главный; `google-script.gs` в репозитории — копия, держать в синхроне):
1. Таблица → «Расширения → Apps Script» → правка → «Сохранить».
2. «Начать развертывание → Управление развертываниями → ✏ изменить → Версия: **Новая версия** → Развернуть». Адрес API при этом не меняется.
3. **Откат**: там же выбрать предыдущую версию.

Адрес API (вписан в index.html как `API_URL`):
`https://script.google.com/macros/s/AKfycbxSXS6WoSei6vke43-jPTfSviFiteAWbnDiKLuB2LbbPoxnYjADNzVkhAvM4dWT9LYdaA/exec`

**Свойства скрипта** (Apps Script → ⚙ Настройки проекта → Свойства скрипта, значения только там):
- `MAX_TOKEN` — ключ бота MAX;
- `MAX_CHAT_ID` — ID чата «АДМИНЫ АППЕТИТ». Находится сам функцией `testMax` по свежим событиям бота: если чат не находится, удалить и снова добавить бота в чат, затем запустить `testMax`;
- `IIKO_API_KEY`, `IIKO_APP_ID`, `IIKO_CLIENT_SECRET` — для сверки с iiko (пока не внесены).

**Служебные функции** (запуск вручную в Apps Script):
- `testMax` — проверка бота и поиск чата; отправляет одно сообщение «🔧 ТЕСТ»;
- `testMaxSend` — тестовое сообщение;
- `setupBackup` — включить ночную резервную копию (уже включена);
- `backupDaily` — сделать копию сейчас;
- `iikoTest` — проверка подключения iiko и полей OLAP;
- `clearTestData` — разовая очистка тестовых данных перед запуском; после использования удалить.

## 6. MAX (чат админов)

- API MAX: `platform-api2.max.ru`. Сертификат УЦ Минцифры, серверы Google его не принимают, поэтому запросы идут через посредника.
- `MAX_RELAY` в скрипте = `https://functions.yandexcloud.net/d4ea85u3v2tqfi0e5mc6`. Посредник пропускает только запросы `/me`, `/chats/{id}`, `/updates` и отправку сообщения в чат. Ключ бота в нём не хранится, его передаёт скрипт.
- `GET /chats` (список чатов) MAX убрал в июне 2026 года, поэтому ID чата берётся из событий бота.
- Тестовые сообщения в чат обязательно помечать «ТЕСТ».

## 7. iiko

- **Сверка выручки по типам оплат** — через iikoCloud API (`api-ru.iiko.services`, `/api/reporting/v1/olap/get`).
  - Нужна регистрация приложения в кабинете разработчика iiko (public-api.iikoweb.ru/portal): appId и clientSecret, плюс ключ API из iikoWeb. Всё вписывается в «Свойства скрипта».
  - Поля OLAP заданы в `IIKO_F` в скрипте; проверить их функцией `iikoTest`.
- **Остатки по счетам** iiko можно брать через `/api/finance/v1/balance-sheet/list`. Это следующий шаг: автосверка с вкладкой «Касса».
- **Создание проводок** (занесение приходов и расходов в кассы по плану счетов) этот API, судя по документации, не умеет. Поддержка iiko (заявка 387235632) подтвердила: проводки через API нельзя, можно только документы (акт реализации — не подходит для кассовых расходов). Поэтому приходы/расходы заносятся вручную по сводке «В iiko» с галочками. Server API: `https://appetit-ufa-co.iiko.it:443/resto/` (логин/пароль API-пользователя — в «Свойства скрипта», пока не заведён).
- Кассы в плане счетов iiko: Касса Аппетит 1.01, Казань Ильгама Шакирова 1.01.01, Ямашева 1.01.02, Глушко 1.01.03, Хади Такташа 1.01.04, Челябинск 1.01.07, Тюмень 1.01.08, Уфа 1.01.09.

## 8. Банк и агрегаторы (в работе)

- ИП Голубев — Альфа-Банк. Отчёты по терминалам и онлайн-оплате выгружаются **общим файлом по ИП**, без разбивки по филиалам.
- Решили: Алина будет **загружать выгрузки вручную**. Сверка по ИП за день: сумма «Карта» и «Онлайн» всех филиалов ИП против реестра. При расхождении показывать цифры по филиалам. Если в реестре есть номер терминала — разносить по филиалам.
- Ночные оплаты до 05:00 относить к предыдущей смене.
- Ждём от Алины примеры файлов (реестр терминалов, онлайн-оплата) и список филиалов на ИП Голубев. Уфа с сентября 2026 года на другом ИП.
- API Альфы (H2H) требует клиентский сертификат и постоянный IP — пока не делаем.

## 9. Безопасность

- Никогда не вводить за Алину пароли, PIN-коды, токены и ключи. Она вносит их сама в «Свойства скрипта» или на лист «Админы».
- PIN-коды iiko не копировать.
- Удаление данных — только по её подтверждению и её же нажатием.
- Внешние ключи, присланные в чат, никуда не переносить.
